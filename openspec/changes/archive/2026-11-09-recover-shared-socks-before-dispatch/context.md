The direct Python Responses transport uses the shared HTTP generation's SOCKS connector. Its selected account does not choose that proxy. Only typed pre-dispatch proxy errors on that actual connector establish this scope; an environment variable or arbitrary error message alone is insufficient. A dedicated `ResolvedUpstreamRoute` uses its private Codex client and remains endpoint scoped. Native-helper errors lack equivalent typed SOCKS provenance and are outside this correction.

A shared SOCKS CONNECT timeout can retry the same request/account within the original deadline because no upstream request bytes were dispatched. Existing recovery owns generation retirement, backoff and exhausted-budget settlement. Post-connect stream failures remain ambiguous and gain no retry eligibility. This forward correction does not establish the cause of historical cache misses or repair past requests.
